Shared protocol · applies to every approved feature

Linear integration protocol

Every approved feature gets pulled into Linear under a consistent structure so it slots into the existing Brite workflow commands (/workflows:create-issues, /workflows:session-start, /workflows:review, /workflows:ship) without ad-hoc shaping.

Standard fields per issue

  • Project: Brite LMS · Team: Brite Company (BC)
  • Labels: type:task · executor:hybrid · size (S or L) · requires-security-review for F01 + F10
  • Priority: per utilitarian phasing — Urgent for F10, High for F07 + F09, Medium for the rest
  • Status: Backlog until sprint planning pulls into a cycle
  • Estimate: Linear points (1 ≈ ½-1 day, 2 ≈ 1-2 days, 13 ≈ 3-4 weeks)
  • Description: full spec with Decision, Implementation plan, AC, Touch points, Non-goals, Cross-references

Workflow command alignment

PhaseWorkflow commandWhat happens
Sequence/workflows:sprint-planningAssigns Phase 1 issues to a cycle first
Pick up/workflows:session-startPulls next unblocked issue, fetches AC + parent context
Plan/workflows:writing-plansBreaks into 2-5 minute tasks
Build/workflows:executing-plansTDD per task, two-stage review
Review/workflows:reviewParallel review agents — fix P1s before PR
Ship/workflows:shipPR + Linear update + compound learnings + handbook-drift check

Cross-cutting requirements

  • Mobile parity: every feature works on phones (gloves-on field reality)
  • Accessibility: keyboard navigable, screen-reader labeled, WCAG AA contrast, respects prefers-reduced-motion
  • Schema discipline: any new table uses prisma migrate dev --name <change> per BC-6368 lessons — never db push for schema history
  • Existing patterns: reuse shadcn primitives before introducing new dependencies
  • Compound learnings: post-ship, surprising decisions get a 1-line entry in docs/patterns/<area>.md

Feature 01 · Approved 2026-05-07 · BC-7010

Cmd+K command palette → upgrade Brite AI engine

GitBook · Notion · Mintlify · Linear · Slab
✓ ApprovedPhase 2/3Effort: L (~3-4 wk)SearchExisting surface

Decision

Keep the Brite AI branding and entry-button. Replace the engine underneath. Expand the panel from a single-purpose substring search (current SQL ILIKE) into a two-mode command palette: Search (default, FlexSearch fuzzy match) + Ask AI (RAG over same corpus, Anthropic API). One feature, two entry points (Cmd+K + button), one data source.

★ User reasoning

"I like that path, keep the branding but change the bones." Single entry point avoids decision fatigue for field workers — Search is the default (cheap, fast); Tab key escalates the same query to AI mode if results are weak.

Architecture decision (locked)

FlexSearch (in-process JS index) over Pagefind (Pagefind is build-time-only, incompatible with ISR revalidate). For ~196 modules, FlexSearch fits comfortably in memory and rebuilds on the same hook as ISR.
